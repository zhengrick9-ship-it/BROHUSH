# 2DOGS 世界杯投注看板设计

## 目标

将现有 BRORUSH 页面升级为 2DOGS 世界杯共同投注看板。木四与听课的投注完全一致，因此数据库按单人票面保存，页面统一按两人合计展示，不做分人统计。

## 视觉

- 保留现有浅暖米色、陶土橙和深灰色基线。
- 借鉴 Anthropic 官网的编辑式排版：衬线大标题、克制的小号标签、细分隔线、宽松留白。
- 品牌名称改为 `2DOGS`，使用原创线性 SVG 图标表示柴犬和可卡犬。
- 不引入重型图表或动画库，保持页面轻量。

## 页面结构

1. 登录页：显示 2DOGS 双犬标识，允许输入木四或听课。
2. 顶部：品牌、当前身份、退出。
3. 概览：累计投入、完赛投入、完赛收益、ROI、战绩。
4. 三条资金线：累计投入、完赛投入、累计返奖，使用相同金额尺度。
5. 轮次导航：横向滚动标签，默认选中最早包含未完赛比赛的轮次。
6. 比赛明细：每场展示日期、对阵、模型推荐、共同实际投注、金额、赛果和收益。
7. 编辑区：在同一比赛行中修改赛果和共同投注，保存后写入数据库。

## 数据模型

- `matches` 增加 `stage`、`round_number`、`kickoff_at` 字段。
- `bets` 保留单人单注金额，同一比赛允许多注。
- 增加票据与串关腿数据，支持单关、6×1 和多过关组合结算。
- 清理当前两批重复投注，只保留一批；展示和收益统一乘以 2。
- 投注结果和收益由比赛赛果计算，数据库中的 `result`、`profit` 作为持久化快照。
- API 仅返回共同投注，不再生成虚假的 `person` 字段。

## 安全

- 从仓库删除硬编码 `service_role` 密钥和危险同步脚本。
- 浏览器不持有管理密钥。
- 读接口可公开；写接口要求服务端访问密码 Cookie。
- 写接口使用独立的 `SUPABASE_SERVICE_ROLE_KEY` 环境变量。
- 用户必须在 Supabase 后台轮换已泄露的管理密钥，并执行迁移。

## 错误处理

- API 对配置缺失、数据库错误、输入错误和未授权分别返回明确状态码。
- 前端显示载入、保存、成功和失败状态。
- 空比分不会被解释为 `0:0`。

## 测试

- 单元测试覆盖汇总指标、投注结算、轮次归类和趋势点。
- TypeScript 检查与生产构建不再跳过。
- 浏览器验收覆盖登录、轮次切换、响应式布局和编辑入口。
